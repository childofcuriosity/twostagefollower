# Supplement: actual-execution controls with reduced operation context

Registered 2026-09-25 while the main matrix was running, before any outputs from this supplement. Motivation comes from the existing32B/512-step correct-name test: the operation-only model is correct on the first three calls of all 288 eight-tool examples, yet later develops new errors even when prior operations are all correct. Error imitation alone therefore cannot explain every failure.

Question: with tool order already supplied, is long operation history an intervenable source of failure? Does the advantage of separate training persist after reducing operation context?

Intervention: name generation retains the complete original task and actual generated history. Operation generation receives a single-tool task under the same protocol, with initial state taken from the actual previous call and tool name just generated by the model. The name is not the reference answer and state is not corrected. Operation outputs are appended to the real global trajectory; the name model chooses the next tool or Done. Invalid names, malformed operations, and early stopping fail as usual, without forcing the requested call count.

This changes context scope: it removes both the global tool list and executed history from the operation model and converts input to an in-training single-tool format. It is neither a token-length-only effect nor a new training method. The program does not execute correct operations or consult references for correction.

Fixed matrix: existing3B/32B models, seeds11/22/33, fixed 512 steps. Four routes: joint names/joint operations; sequence specialist/joint; joint/operation specialist; sequence specialist/operation specialist. Each tests dev 224 plus independent 480, totaling 16896 new trajectories, paired example by example with main-matrix full-history versions. At each scale, seed11 uses 40 examples to verify exact agreement between the new full-mode evaluator and the original evaluator, two execution methods each,160 calibration trajectories total. Main reduced-context runs start only after passing.

Retain batch8, greedy decoding, global generation and protocol budgets, without test-based checkpoint selection or extra training. Report all four routes, not just the best. Primary comparisons: full versus local operation context within each route; specialists versus joint training within local context.

If the joint model also recovers, this primarily supports operation-context scope as an important intervention point in this task, not the necessity of separate training. If specialist gains remain consistent, discuss complementary training/context effects. If unstable, locate name/operation/termination errors record by record; launching jobs or a positive single seed is not completion.

Audits must retain both global trajectory prefixes and actual model generation contexts, independently reconstruct local inputs from selected names and actual states, and check tokens, hashes, and scores to exclude answer injection. New source is separate from main-matrix source. Use local resources after main-matrix completion.

## Testable expectations before inference

In existing 512-step program-correct-operation tests,32B joint sequence success on long tasks is 476/480,472/480,469/480, versus 469/480,464/480,480/480 for sequence specialists. If local context makes operations nearly perfect, the joint 32B model may itself recover strongly and separate training may add little. That would limit claims that separation is necessary, not constitute experimental failure.

For 3B on earlier hardware, corresponding joint counts are 253/480,159/480,251/480, versus 403/480,200/480,386/480 for sequence specialists, suggesting a greater chance of retained specialist benefits. These 3B expectations come from old hardware; formal controls use new local inference. They are references under nearly perfect operations, not results of the unrun local-context experiment.
