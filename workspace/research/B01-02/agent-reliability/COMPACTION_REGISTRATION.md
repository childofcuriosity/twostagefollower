# Public-state handoff compaction

Motivation: explicit-note identity and reminder each completed all three12-ticket confirmation tasks. The first24-ticket identity task delivered15 correctly then exhausted context. Full-history imitation copies old records/code, so a fixed context can prevent long completion even if local computation is correct. Continue solving this obstacle.

Intervention: after a delivery receipt, replace older conversation with original system/user request, a deterministic summary of already observed receipt IDs/count, and the most recent assistant/tool exchange. Keep all workspace files. The summary explicitly says receipt is not correctness; future ticket data and hidden expected values are not used. The model can still end at any time; no validator-based stop gate or automatic task execution is added. Retain exact per-turn prompt messages and every original model output/tool result for audit. This is a controller memory/context intervention, not proof of model-learned identity or weight-level improvement.

Budgets and other prompts match native_queue_notes.py (24k generated tokens,128 turns,30k context,2400seconds). Zero-shot only. Calibration: both baseline and identity on two four-ticket dev cases,4/4 required. Main: all four note conditions on the three existing24-ticket confirmation instances (paired engineering regression against full history), plus three new24-ticket seeds20266001–3 (independent confirmation),24 trajectories total. Preserve all failures and compare completed reports, premature stopping, context/token limits, total generated/prefill tokens and wall time. Note differences are controlled within the compact version; full-versus-compact comparison bundles deletion with a public-state summary, so their separate effects are not identified.
