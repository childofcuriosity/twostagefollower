# Role-marker history ablation and deterministic rerun

Controlled version2 seed20267001: full history correctly delivered5/24 then ended, while compaction delivered24/24. The first6 model/tool turns were byte-identical before compaction. Full history showed model-generated Human/user/tool_response markers outside genuine calls from turn10 onward; they accumulated, then one generation reached4096 tokens and the model inferred that the remaining tickets had been completed. This motivates a more specific history ablation.

New `sanitize` policy retains full genuine tool history. Only when an assistant message contains valid tool calls, its free-text history content is truncated before the first apparent Human:/Assistant:/user/assistant/tool_response role marker. Original raw generation is preserved, and tool calls/results, operational-note arguments, original goals, budgets, clock/schema/error controls remain unchanged. Final responses without calls are not sanitized or prevented. No extra state or answer information is added. This tests role-marker-content filtering, not semantic identity narration.

Run sanitize on ALL three version2 main tasks, including the already successful full-history case; no case selection. Also repeat full-history seed20267001 with the same version3 executable but filtering disabled to check deterministic failure reproduction. Four trajectories, registered before inference. The main9 version2 runs and all preceding failures remain intact. This follow-up is exploratory; results do not establish novelty, other-model generality, or that all premature finishes share this mechanism.
